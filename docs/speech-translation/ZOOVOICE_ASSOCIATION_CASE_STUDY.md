# Zoovoice連想の改善: 辞書・Embedding・LLMを同じ50問で比べた記録

更新日: 2026-08-08

Zoovoiceは発話の内容から動物を1種連想して鳴き声を重ねる。その連想を賢くするために何を作り、実測でどう判断したかを実例で説明する。仕様の正本は [SPEC.md](SPEC.md) であり、この文書は仕様を定めない。連想の設計解説はSPEC.mdや `services/zoovoice/README.md` に収まらない量のため、比較再生と同じケーススタディ形式の別文書にした。

要点:

- 連想語の抽出改善は本番へ入れた。ゴミ語が消え、ひらがな読みでも辞書を引けるようになった。
- WordNet同義語展開は効果ゼロ、Embedding連想は50問中1問の改善に留まった。
- 同じ50問をLLM（gpt-5.6-luna）に解かせると、動物を期待する30問の正解が14→29問へ跳ねた。
- 手がかりの薄い発話にも「眠れない→羊を数える」のような気の利いたこじつけを返せた。
- 結論として連想はLLMへ一本化し、辞書の連想経路は全廃する方針にした。

## 用語

| 用語 | 意味 |
| --- | --- |
| 語彙表（レキシコン） | 27動物の名前と鳴き声の言葉を集めた一覧表。自作の生成物。 |
| ConceptNet | 「カエルは池にいる」のような常識のつながりを集めた公開データ。 |
| 1-hop / 2-hop | つながりをたどる歩数。「池→カエル」で1歩（1-hop）。 |
| 意味ベクトル（Embedding） | 文を数値の並びへ変換したもの。意味が近い文は近い数値になる。 |
| random | どの経路でも決まらないとき、当てずっぽうで1種選ぶ最終手段。 |

## 使っている辞書・モデルと出所

| 辞書・モデル | 内容 | 出所 | 置き場所 |
| --- | --- | --- | --- |
| 語彙表 | 27動物の名前・鳴き声の言葉 | ConceptNet候補をAI判定で選別した自作生成物 | リポジトリ内 `assets/` |
| ConceptNet 5.7.0 | 常識のつながり。日本語部分25万本 | MIT発の公開知識グラフ（帰属は `LICENSE-CONCEPTNET.md`） | リポジトリ外SQLite |
| 日本語WordNet 2.0 | 同じ意味を持つ言葉の組（299万組） | NICT公開の概念辞書 | リポジトリ外SQLite |
| ruri-v3-70m | 文を意味ベクトルへ変換する日本語軽量モデル | cl-nagoya公開モデルをONNX int8化 | リポジトリ外 |
| gpt-5.6-luna | 比較実験に使ったLLM | OpenAI API | 外部API |

JMdict（日英辞書）の擬音語も診断CLIで試したが、動物への対応付けを機械抽出できず不採用にした。

## 入力から結果までの実例

連想は「言葉の抽出 → 語彙表と直接一致 → 語呂合わせ → ConceptNet 1-hop → random」の順に試す。実際の入力がどの経路で決まるかを、評価50問の実例で示す。

**直接一致で決まる例**

> 「今日もうちのペットはにゃーにゃー鳴いてる」
> → 抽出した「にゃーにゃー」が語彙表の鳴き声「にゃー」に一致 → **猫**（正解）

**ConceptNetのつながりで決まる例**

> 「池でゲロゲロと鳴いていた」
> → 抽出した「池」→ つながり `カエル -[〜にいる]→ 池` → **カエル**（正解）

> 「空を飛んでいる夢を見た」
> → 抽出した「飛ぶ」→ つながり `カラス -[〜できる]→ 飛ぶ` → **カラス**（正解）

**経路は出るが正解でない例**

> 「今日も暑い。砂漠みたいな暑さだ。喉が渇いたな」
> → 抽出した「のど」→ つながり `のど -[関連 0.4]→ カエル` → **カエル**（期待はライオンやゾウ。弱いつながり1本で決まってしまった）

**どの辞書でも届かずrandomになる例**

> 「縞模様の服を買った」（期待は虎）
> → 「縞」「模様」「服」のどれも、27動物への1歩のつながりを持たない → **random**

### なぜ2-hop以上へ増やさないのか

歩数を増やせば届く先は増えるが、正しい連想より先にでたらめな連想が増える。上の「縞模様の服を買った」を実験用の2-hop探索で引くと、最上位は虎ではなく猫になる。

> `服 -[〜にある]→ ベッドルーム ←[〜にいる]- 猫`（重み2.00）
> `縞 ←[派生語]- 縞馬 → シマウマ`（重み1.00。ただし鳴き声音源がなく選べない）

「ベッドルーム」「種類」「デザイン」のような何にでもつながる言葉を経由すると、どんな入力もどこかの動物へ届いてしまう。歩数を増やすほどこの誤連想が上位を占め、重み付けでは抑えきれなかった。このため本番は1-hopに固定し、2-hop以上は診断CLIだけに残している。

## 実装前後の比較（同じ50問）

「明示」「情景」「比喩」の30問と「手がかりの薄い発話」20問の計50問を固定して比べた。指標は2つで、「経路つき」はrandomでなく根拠つきで動物を選べた数、「正解」は動物を期待する30問のうち期待どおりの動物を選べた数である。

| 方式 | 経路つき | 正解（30問中） |
| --- | --- | --- |
| 実装前: 旧抽出 + 辞書 | 21/50 | 14/30 |
| 実装後: 新抽出 + 辞書（本番採用） | 22/50 | 14/30 |
| 実装後 + WordNet同義語展開 | 22/50 | 14/30 |
| 実装後 + Embedding補欠 | 23/50 | 15/30 |
| 参考: LLM（gpt-5.6-luna、こじつけ歓迎プロンプト） | 50/50 | **29/30** |

### 抽出改善で何が変わったか

「にゃーにゃー鳴いてるやつがいる」の抽出語は、旧「ー / ー鳴い / ー鳴いてる / てる / ヤツ …」から新「にゃーにゃー / 鳴い / 鳴く / ない / いる」になった。ゴミ語が消え、読みはカタカナに加えひらがなでも辞書を引く。

50問で結果が変わったのは「喉が渇いたな」である。旧抽出は読みが「ノド」だけでConceptNetに一致せずrandomだった。新抽出は「のど」で引けて経路を出せた。ただし選ばれたのはカエルで、経路を出せる入力は増えたが正解は増えていない。処理時間は1入力4.3→6.1マイクロ秒で、実用上の差はない。

### WordNetはなぜ効かなかったか

辞書で引けない言葉を同義語へ広げても、別の意味の同義語ばかりが出た。

> 「犬の散歩に行ってきた」の展開語 →「まわし者」「お拾」「いらっしゃる」（「犬=スパイ」などの別義。動物へ届かない）
> 「縞模様」の展開語 →「筋」→ つながり `七面鳥 -[〜を持つ]→ 筋` → 七面鳥（期待は虎。誤った方向へ届いてしまう）

50問で結果が変わった入力は0件だった。言葉の言い換えでは、動物と結びつかない入力を救えない。

### Embeddingはどこまで効いたか

辞書で決まらないときだけ、文全体の意味ベクトルを27動物の説明文と比べる補欠経路を試した。改善は1問だけだった。

> 「羽を広げてとてもきれいだった」
> → 辞書は全段一致なし → 文と各動物の類似度を計算 → 最上位クジャク（類似度4.40）→ **クジャク**（正解）

処理時間は1件425〜732msで実用範囲である。類似度4.0未満は採用せずrandomへ落とす設計にしたため、手がかりの薄い20問はすべてrandomのままだった。しきい値を安全側に置くと救える入力もほぼ残らず、意味ベクトルの近さだけでは気の利いたこじつけも作れない。

## LLMに同じ50問を解かせた結果

辞書とEmbeddingの改善が頭打ちだったため、gpt-5.6-lunaに27候補と発話を渡して1種選ばせた。プロンプトは2回試した。

1回目は「手がかりがなければ選ばない」を許す慎重なプロンプトにした。動物30問の正解は27/30と高かったが、「首がとても長い動物」でキリンが候補にないため回答を避けるなど、遠慮した無回答が出た。Zoovoiceはこじつけでも動物を選んで鳴き声を返す遊びの製品なので、この慎重さは製品意図に合わない。

2回目は「どんなこじつけでも構わないから必ず1種選ぶ」プロンプトへ変えた。動物30問の正解は29/30になり、**辞書が落とした比喩9問も全問正解した。** 例:

> 「夜になると遠くで遠吠えが聞こえる」→ 狼（理由: 夜の遠吠えからオオカミを連想）
> 「縞模様の服を買った」→ 虎（理由: 縞模様からトラを連想）
> 「毛を刈って糸にすると聞いた」→ 羊（理由: 毛を刈って羊毛を糸にするため）
> 「首がとても長い動物の写真を見た」→ ガチョウ（理由: 首の長い鳥といえばガチョウ）

唯一の不正解も「砂漠みたいな暑さだ」→ キツネ（砂漠に住むフェネックを連想）で、連想としては筋が通っている。期待リスト側が狭かったと見るべき結果だった。

**手がかりの薄い20問にも、全問に気の利いた連想を返した。** 辞書方式ではrandomになるしかない入力である。

> 「眠くて集中できない」→ 羊（理由: 眠る前は羊を数えてしまう）
> 「財布を忘れた」→ ブタ（理由: 財布といえばブタの貯金箱）
> 「将来のことを考えると不安」→ フクロウ（理由: 不安=苦労を避けたい、フクロウ「不苦労」）
> 「予約を変更した」→ カエル（理由: 予約を「変える」→カエル）

語呂合わせ・ことわざ・縁起物まで使い分けており、この質のこじつけは辞書のつながりでは作れない。

## 結論と今後の方向性

連想はLLMへ一本化し、辞書の連想経路は全廃する。直接の言及もLLMが普通に当てるため、直接一致の段を辞書で残す理由もない。ConceptNet・WordNet・Embedding・語彙表の連想語彙（動物の別名や鳴き言葉の一覧）は、すべて退役の対象になる。

製品構造として残るのは次の2つだけである。

- **音源カタログ**: どの動物に鳴き声音源があるかの対応表。LLMへ渡す候補リスト27種と、最終手段randomの母集団の出どころになる。連想の知識は持たない。
- **randomの最終手段**: 外部APIの障害・タイムアウト時に、音源カタログから1種選ぶ。

実装へ進む際の論点は次の2つである。

1. **費用と応答時間**: LLMは1リクエストごとに外部APIの往復と課金が発生する。SpeakLoopで実績のあるOpenAI経路を使えるが、Zoovoiceの合成フローに許容できる遅延かは実測が要る。発話内容が外部APIへ渡るようになるため、公開デモのプライバシー説明の更新も必要になる。
2. **プロンプトが製品の性格を決める**: 慎重版と必ず選ぶ版で結果が大きく変わった。Zoovoiceは必ず選ぶ版が合う。連想の理由も短文で返せるため、UIで理由を見せる拡張も選べる。

Embedding・WordNet・LLMの評価一式はローカル実験として残した。再実行の方法は `services/zoovoice/README.md` と `tools/rensou_dict.md` を参照。LLM評価は `tmp/llm-association/` のスクリプトで再現できる。
