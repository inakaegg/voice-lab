# Zoovoice連想の改善: 辞書の拡張とEmbeddingを試した記録

更新日: 2026-08-08

Zoovoiceは発話の内容から動物を1種連想して鳴き声を重ねる。その連想を賢くするために何を作り、実測でどう判断したかを実例で説明する。仕様の正本は [SPEC.md](SPEC.md) であり、この文書は仕様を定めない。連想の設計解説はSPEC.mdや `services/zoovoice/README.md` に収まらない量のため、比較再生と同じケーススタディ形式の別文書にした。

要点:

- 連想語の抽出改善は本番へ入れた。ゴミ語が消え、ひらがな読みでも辞書を引けるようになった。
- WordNet同義語展開は効果ゼロだった。別の意味の同義語ばかり出るためで、本番へ入れない。
- Embedding連想は50問中1問だけの改善だった。ローカルで試せる状態に留めた。
- 残る失敗は比喩の入力に集中しており、次の一手はLLMによる連想を検討している。

## 使っている辞書と出所

| 辞書・モデル | 内容 | 出所 | 置き場所 |
| --- | --- | --- | --- |
| 動物レキシコン | 27動物の名前・鳴き声語彙。連想と音声再生の正 | ConceptNet候補をAI判定で選別した自作生成物 | リポジトリ内 `assets/` |
| ConceptNet 5.7.0 | 「カエル←池にいる」のような概念のつながり。日本語部分25万エッジ | MIT発の公開知識グラフ（帰属は `LICENSE-CONCEPTNET.md`） | リポジトリ外SQLite |
| 日本語WordNet 2.0 | 同じ概念を持つ日本語語彙の組（同義語299万組） | NICT公開の概念辞書 | リポジトリ外SQLite |
| ruri-v3-70m | 文を意味ベクトルへ変換する日本語軽量モデル | cl-nagoya公開モデルをONNX int8化 | リポジトリ外 |

JMdict（日英辞書）の擬音語も診断CLIで試したが、動物への対応付けを機械抽出できず不採用にした。

## 入力から結果までの実例

連想は「語の抽出 → レキシコン直接一致 → 語呂合わせ → ConceptNet 1-hop → random」の順に試す。実際の入力がどの経路で決まるかを、評価50問の実例で示す。

**直接一致で決まる例**

> 「今日もうちのペットはにゃーにゃー鳴いてる」
> → 抽出語「にゃーにゃー」がレキシコンの鳴き声「にゃー」に一致 → **猫**（正解）

**ConceptNetのつながりで決まる例**

> 「池でゲロゲロと鳴いていた」
> → 抽出語「池」→ ConceptNetの辺 `カエル -[AtLocation]→ 池`（カエルは池にいる）→ **カエル**（正解）

> 「空を飛んでいる夢を見た」
> → 抽出語「飛ぶ」→ 辺 `カラス -[CapableOf]→ 飛ぶ`（カラスは飛べる）→ **カラス**（正解）

**経路は出るが正解でない例**

> 「今日も暑い。砂漠みたいな暑さだ。喉が渇いたな」
> → 抽出語「のど」→ 辺 `のど -[RelatedTo 0.4]→ カエル` → **カエル**（期待はライオンやゾウ。弱い辺1本で決まってしまった）

**どの辞書でも届かずrandomになる例**

> 「縞模様の服を買った」（期待は虎）
> → 抽出語「縞」「模様」「服」はどれも、27動物への1-hopの辺を持たない → **random**
> 実験用の2-hop探索なら `縞 ←[DerivedFrom]- 縞馬 → シマウマ` が見えるが、シマウマは音源のない動物で選べない。虎へは2-hopでも届かない。

## 実装前後の比較（同じ50問）

「明示」「情景」「比喩」「連想なし」の4種50問を固定し、randomでなく根拠つきで動物を選べた数（経路つき選択）を数えた。「連想なし」20問はrandomが正解である。

| 方式 | 経路つき選択 | 変化 |
| --- | --- | --- |
| 実装前: 旧抽出 + 辞書 | 21/50 | 基準 |
| 実装後: 新抽出 + 辞書（本番採用） | 22/50 | +1 |
| 実装後 + WordNet同義語展開 | 22/50 | ±0 |
| 実装後 + Embedding fallback | 23/50 | +1 |

### 抽出改善で何が変わったか

「にゃーにゃー鳴いてるやつがいる」の抽出語は、旧「ー / ー鳴い / ー鳴いてる / てる / ヤツ …」から新「にゃーにゃー / 鳴い / 鳴く / ない / いる」になった。ゴミ語が消え、読みはカタカナに加えひらがなでも辞書を引く。

50問で結果が変わったのは上の「喉が渇いたな」である。旧抽出は読みが「ノド」だけでConceptNetに一致せずrandomだった。新抽出は「のど」で引けて経路を出せた。ただし上記のとおり選ばれたのはカエルで、経路を出せる入力は増えたが正解精度までは上がっていない。処理時間は1入力4.3→6.1マイクロ秒で、実用上の差はない。

### WordNetはなぜ効かなかったか

辞書で引けない語を同義語へ広げても、別の意味の同義語ばかりが出た。

> 「犬の散歩に行ってきた」の展開語 →「まわし者」「お拾」「いらっしゃる」（「犬=スパイ」などの別義。動物へ届かない）
> 「縞模様」の展開語 →「筋」→ 辺 `七面鳥 -[HasA]→ 筋` → 七面鳥（期待は虎。誤った方向へ届いてしまう）

50問で結果が変わった入力は0件だった。語の言い換えでは、動物と結びつかない入力を救えない。

### Embeddingはどこまで効いたか

辞書で決まらないとき、文全体の意味ベクトルを27動物の説明文と比べる。改善は1問だけだった。

> 「羽を広げてとてもきれいだった」
> → 辞書は全段一致なし → 文と各動物の類似度を計算 → 最上位クジャク（類似度4.40、しきい値4.0以上）→ **クジャク**（正解）

処理時間は1件425〜732msで実用範囲である。類似度4.0未満は採用せずrandomへ落とすため、「連想なし」20問を誤って動物へ結びつける事故はなかった。逆に言えば、しきい値を安全側に置くと救える入力もほぼ残らない。

## 何が問題として残ったか

改善後も9問が失敗しており、比喩の入力に集中している。「夜になると遠くで遠吠えが聞こえる」→狼、「毛を刈って糸にすると聞いた」→羊のような入力である。「遠吠え」や「毛を刈る」と動物を結ぶ辺が辞書になく、語の言い換えでも意味ベクトルのしきい値内でも届かない。文全体の意味理解が要るため、辞書の拡張を重ねるよりLLMに連想させる方が筋がよいと判断し、次の候補として検討している。

EmbeddingとWordNetは、この評価基盤ごとローカル実験として残した。再実行の方法は `services/zoovoice/README.md` と `tools/rensou_dict.md` を参照。
