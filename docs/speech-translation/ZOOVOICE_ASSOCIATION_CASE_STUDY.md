# Zoovoice連想の改善: 辞書の拡張とEmbeddingを試した記録

更新日: 2026-08-08

Zoovoiceの動物連想を賢くするために何を作り、実測でどう判断したかを説明する。仕様の正本は [SPEC.md](SPEC.md) であり、この文書は仕様を定めない。連想の設計解説はSPEC.mdや `services/zoovoice/README.md` に収まらない量のため、比較再生と同じケーススタディ形式の別文書にした。

要点:

- 連想語の抽出改善は本番へ入れた。同じ辞書でも引ける入力が増える。
- WordNet同義語展開は効果ゼロだったため本番へ入れない。
- Embedding連想はわずかな改善だったため、ローカルで試せる状態に留めた。
- 次の一手はLLMによる連想を検討している。

## 用語

| 用語 | 意味 |
| --- | --- |
| ConceptNet | 「北極→白熊」のような概念のつながりを収めた辞書。現行連想の中心。 |
| WordNet同義語 | 日本語WordNetから作った言い換え辞書。「毛」→「羊毛」のように広げる。 |
| Embedding | 文を数値の並び（意味ベクトル）へ変換する技術。意味が近い文は近い数値になる。 |
| 連想経路提示率 | 評価入力のうち、当てずっぽうでなく根拠つきで動物を選べた割合。 |

## 何を作ったか

1. **連想語の抽出改善（本番反映）**: 形態素解析の分割モードを見直し、名詞など連想に効く品詞だけを残すようにした。読みをカタカナとひらがなの両方でConceptNetへ照会し、「にゃーにゃー」のような繰り返し擬音も1語として復元する。
2. **公平な評価基盤**: 「明示」「情景」「比喩」「連想なし」の50問と最終判定38問のfixtureを作り、方式を同じ条件で比べるCLI（`association-eval`）を追加した。
3. **WordNet同義語展開（試作）**: ConceptNetで引けない語を同義語へ広げて再照会する方式。
4. **Embedding連想（ローカル実行可）**: 辞書で決まらないときだけ、文全体の意味ベクトルを27動物の説明文と比べて選ぶ。軽量ONNXモデル（ruri-v3-70m int8）を都度起動の別プロセスで動かす。環境変数4つを設定した環境でだけ有効になる。

## 実測結果

同じ50問（開発用）に対する連想経路提示率の比較。

| 方式 | 経路つき選択 | 変化 |
| --- | --- | --- |
| A: 抽出改善後の辞書のみ | 21/50 | 基準 |
| W: A + WordNet同義語展開 | 21/50 | ±0 |
| E: A + Embedding fallback | 22/50 | +1 |

最終判定38問では3方式に差が出なかった。Embeddingの1件あたり処理時間は425〜732ms（ローカル実測）で、速度とメモリは実用範囲だった。

## 判断

- WordNet展開は、辞書で引けない入力は同義語でも引けないことが多く、効果が出なかった。
- Embeddingは動くが、辞書で決まらない入力の多くは「連想なし」が正解の入力でもあり、伸び幅が小さかった。
- そのため本番はA（抽出改善のみ）とし、EmbeddingとWordNetは評価基盤つきのローカル実験として残した。
- 情景や比喩から動物へ至る連想は、文の意味理解が要るためLLMの利用を次の候補として検討している。
