# Zoovoice 音源の方針（CONCEPT詳細）

更新日: 2026-08-09

本ファイルは `CONCEPT.md` の大原則を詳細化した人間向けの正本である。`docs/` や `SPEC.md` の記述と食い違う場合は本ファイルを優先する。矛盾したら `CONCEPT.md` の大原則が常に最上位となる。

## 取得方針

- 鳴き声は生成音声ではなく、実録音の音声ファイルを無償で取得する。同じ動物に実録音と生成音の両方があるときは必ず実録音を採る。
- 対象動物の正本は実際の音声ファイル（セットの `manifest.json`）である。[ANIMALS.md](ANIMALS.md) はそこから作り直す写しであり、手で書き換えない。
- 動物名と実音声ファイルの対応リスト（鳴き声リスト）を正とし、実装はそこから参照する。

## ライセンス方針

- 第一候補: CC0またはパブリックドメイン。
- 第二候補: CC BY。採用した場合は帰属表示を必ず行う。
- 不採用: NC・SA・NDを含むライセンス。
- 素材ごとの出所と採用hashは、鳴き声セットの `manifest.json` に記録する。
- 素材そのものはリポジトリへ置かず、実行時は `ZOOVOICE_SOUNDS_DIR`、container image ではbuild時に取り込む。

## 正規化仕様

- 24kHz、モノラル、16bit。
- 1本あたり最長30秒。

## トリム加工仕様（無音除去）

取得素材には長い無音や複数の鳴き声区間が混在するため、次の手順で1本の代表区間へ切り出す。

1. 無音判定: ピーク音量から-35dB以下が0.3秒以上続く区間を無音とみなす。
2. 区間検出: 無音以外を鳴き声候補とし、間隔1秒未満の候補は1区間へ統合する。
3. 採用: 統合区間が複数ある場合、平均音量（RMS）が最大の1区間だけを採用する。複数区間の切り貼り結合は、つなぎ目が不自然になるため行わない。
4. 整形: 採用区間の前後へ0.2秒の余白を残し、両端へ1.5秒ずつフェードを掛ける。ぶつ切りを避けるための長いフェードであり、5秒の音声では中央約2秒が本来の音量で残る。区間が短い場合はフェードを区間長の3分の1へ縮める。
5. 長さ: 採用区間は最長5秒とする。超える場合はRMS最大位置を中心に切り詰める。挿入用には鳴き声が短いほど扱いやすいためである。

- しきい値（-35dB・0.3秒・1秒・5秒・フェード1.5秒）は試聴結果に応じて調整してよい。適用値はmanifestへ記録する。
- 挿入処理の側で改めてフェードを掛ける方式（挿入時にフェードイン1.5秒・フェードアウト1.5秒）も選べる。採用するかは挿入処理の設計時に決める。
- CC BY素材は帰属表示へ「無音除去・トリムを実施」と改変の旨を明記する。CC BY 4.0の改変時条件による。

## 旧方針の扱い

- 2026-08-08にStable Audioで44種を試験生成し、実録音と聴き比べた。代表的な種はある程度使えるが、セミなどメジャーでない種は実際と懸け離れた音になった。この結果からも実録音を第一とする方針を維持する。
- 2026-08-09に、生成音が唯一の音源だった14種すべてを実録音へ入れ替えた。これでセットの46種66本はすべて実録音になり、生成音は1本も残っていない。Stability AI関連の表示・文書・取り込みスクリプトも同時に削除した。
- 入れ替えの経路は、Wikimedia Commons API と Openverse API（どちらもAPIキーが要らない）から候補を集め、商用利用できるライセンスだけへ絞り、1本ずつ声の主を確かめて採る、というものである。道具は `scripts/fetch_animal_recordings.py`・`scripts/prepare_animal_recording.py`・`scripts/build_real_recordings.py` に置いた。
- どの候補を採るか、どこを切り出すかという判断はコードへ書かず、リポジトリ外の選定ファイルへ理由つきで残す。効果音として作られた「モンスターの唸り」の類が動物名で配布されていることがあり、名前だけでは選べないためである。
